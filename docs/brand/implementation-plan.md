# План внедрения редизайна «Камень»

Брендбук: `docs/brand/brandbook.md`. Этот план — порядок работ и их цена.
Код интерфейса не меняется, пока владелец не скажет «делай»; этапы можно
запускать по одному.

## Главный риск: слияния с оригиналом

Форк регулярно подтягивает `TheZwiss/backspace`. Цена каждого этапа в
конфликтах разная, и порядок этапов выстроен от дешёвого к дорогому.

| Что меняем | Где | Конфликты при слиянии |
|---|---|---|
| Цвета, шрифт, радиусы, тени, стекло, скорость анимаций | `globals.css`, `tailwind.config.js`, файлы шрифтов | Низкие: два файла, оригинал правит их редко. Конфликт решается за минуты |
| Новые общие компоненты (`Button`, `Icon`, …) | Новые файлы в `components/ui` | Нет: оригинал о них не знает |
| Перевод экранов на общие компоненты, замена иконок, размеры текста | 217 файлов компонентов, 57 тыс. строк | Высокие: любая правка оригинала в том же файле даёт конфликт |

Отсюда два правила:

1. Сначала всё, что даёт вид через токены. После этапа 1 приложение уже
   выглядит как «Камень» на 60–70 %, а к оригиналу добавлено два изменённых
   файла.
2. Экраны переводим в порядке «где форк уже разошёлся с оригиналом»: голосовой
   интерфейс форк и так переписал (PR 7–16), там новые конфликты почти ничего
   не добавляют. Экраны, которые оригинал активно правит, идут последними и
   по одному файлу.

Вариант снять риск совсем — предложить токены и общие компоненты в оригинал.
Это отдельное решение владельца, в план не входит.

## Этап 0. Точка отсчёта

- Снять снимки 23 стендов `packages/web/dev-*.html` до изменений: по ним
  сверяется каждый следующий этап.
- Измерить вес файлов Onest (латиница и кириллица, обычное и курсив).

Объём: без изменений в коде приложения. Конфликты: нет.

## Этап 1. Токены

Один PR. После него вид меняется везде сразу.

1. `globals.css`: нейтральные поверхности, текст, границы, наведение и
   нажатие, служебные цвета, значения стекла (`.glass*`), токены движения,
   кольцо `:focus-visible` вместо глобального `outline: none`.
2. `tailwind.config.js`: шкала радиусов, шкала размеров текста (`2xs`…`2xl`),
   шкала слоёв, шрифт, токены `accent.tone`, `accent.secondary`, `on-accent`,
   `status.ok/warn/danger`.
3. Шрифт: добавить Onest с `OFL.txt`, убрать DM Sans и Inter, убрать правило
   `:lang(ru)`; китайский стек не трогать. Обновить `site/` и
   `scripts/social-preview.html`.
4. Цветовая тема: атрибут `data-accent` на `<html>`, значение хранится
   локально рядом с масштабом интерфейса (`interfaceScaleStore` как образец),
   применяется в `main.tsx` до монтирования React. Выбор темы в «Настройки →
   Внешний вид»; строки в пяти локалях.
5. Документация: `docs/systems/design-system.md` переписать под «Камень»,
   обновить раздел «Design System» в `CLAUDE.md`, `docs/systems/localization.md`
   (шрифты).

Объём: около 12 файлов, из них два «горячих». Конфликты: низкие.
Проверка: стенды до и после, `pnpm lint`, `pnpm dev`, пять языков, масштаб
50 % и 250 %, `prefers-reduced-motion`, `prefers-reduced-transparency`.

Что этап не исправит: произвольные размеры текста (665 мест), произвольные
радиусы (93), `white/…` и `black/…` (623), иконки. Интерфейс станет
«Камнем» по цвету, шрифту и форме, но разнобой в мелочах останется до
этапа 3.

## Этап 2. Общие компоненты

Один PR, только новые файлы в `components/ui` плюс тесты и стенд.

- `Icon` — обёртка над `lucide-react`: размер из шкалы, толщина 1,75.
  Зависимость `lucide-react` добавляется здесь (ISC; в сборку идут только
  импортированные иконки; прирост измерить и записать в PR).
- `Button` (основная, вторичная, тихая, опасная; три высоты), `IconButton`.
- `Tag` (метки «В ЭФИРЕ», качество, язык), `Badge` (счётчик, точка).
- `Card`, `Field` (подпись плюс поле), `Tabs`, `Option` (вариант выбора),
  `Progress`.
- Правка существующих: `Modal` (один радиус, шкала слоёв), `ConfirmDialog`
  (слой из шкалы вместо 10000), `Toggle`, `Tooltip`, `ToastContainer`.
- Правило линтера: прямой импорт `lucide-react` и новые `rounded-[…]`,
  `text-[…px]`, `z-[…]` вне `components/ui` — ошибка. Существующие нарушения
  записываются в `eslint-suppressions.json`, как уже сделано для прочих.
- Стенд `dev-ui-kit.html` со всеми компонентами во всех состояниях и темах.

Объём: 10–12 новых файлов, 5 изменённых. Конфликты: низкие (изменённые
общие компоненты оригинал правит редко).

## Этап 3. Экраны

По одному PR на область, в этом порядке. Каждый PR: перевод на общие
компоненты, иконки Lucide, размеры текста и отступы из шкалы, удаление
`white/…`, `black/…` и цветов мимо токенов в затронутых файлах.

| № | Область | Файлы | Почему в этом порядке |
|---|---|---|---|
| 3.1 | Голосовой канал: сетка, фокус, панель звонка, лента, сведения о соединении | `components/voice` (22) | Форк уже разошёлся с оригиналом; самая заметная часть |
| 3.2 | Каркас: полоса пространств, список каналов, карточка пользователя с «Голосовой связью», шапка, кнопка «Загрузки» | `components/layout` (часть, около 10) | Меняется раскладка левой колонки; файлы оригинал правит часто — делать сразу после очередного слияния |
| 3.3 | Чат: строки сообщений, реакции, поле ввода, вложения, блоки кода | `components/chat` (около 20) | Главный экран; вид вложений из брендбука |
| 3.4 | Окна: общие модальные, меню, карточка профиля, входящий звонок | `components/modals`, `components/ui` (около 25) | В основном замена кнопок и радиусов |
| 3.5 | Настройки пользователя, пространства и сервера | `components/modals/*Panels` (около 30) | Много однотипных строк, мало риска |
| 3.6 | Обзор, друзья, страница Backspace, вход | `components/chat`, `projectHub`, `auth` (около 15) | Отдельные экраны |
| 3.7 | Телефон | `Mobile*` (около 15) | После десктопа: те же компоненты, своя раскладка |

Объём: около 140 файлов из 217. Конфликты: высокие, поэтому каждый PR
начинается со слияния свежего оригинала и сливается быстро.

## Этап 4. Новая функциональность из макета

Это не перекраска; каждая задача отдельным PR со своими тестами.

| Задача | Суть | Затрагивает |
|---|---|---|
| Сворачивание длинных блоков кода | «Показать всё, N строк» | Клиент |
| Автоопределение языка кода | Метка языка без явной пометки после ``` | Клиент; нужна оценка: готовая библиотека весит сотни килобайт, свой определитель для десятка языков — нет |
| Длинная вставка как `pasted.txt` | Текст сверх порога уходит вложением | Клиент, проверка на федерацию (вложение реплицируется как файл) |
| Просмотр файла с кодом в чате | Начало файла в блоке кода, «копировать» и «скачать» | Клиент, сервер (отдача текста с ограничением размера) |

## Этап 5. Вне приложения

- Сайт `site/index.html` и страница метрик: цвета и шрифт.
- README и снимки экрана в `docs/screenshots`.
- Иконка приложения: оставить или перегенерировать под `#6e5bef`
  (`pnpm gen-icons`) — по решению владельца.

## Открытые вопросы

1. Светлая тема: нужна ли. Если да — после этапа 3, вторым набором значений.
2. Фирменный цвет: `#7c6cf6` в иконках против `#6e5bef` в интерфейсе.
3. Раскладка левой колонки (60 + 244 вместо 72 + 240 с наложением): делать в
   этапе 3.2 или оставить нынешние ширины.
4. Выносить ли токены и общие компоненты в оригинал.

## Что считается готовым

Каждый этап: `pnpm lint` и `pnpm dev` без ошибок, тесты проходят, стенды
сверены со снимками этапа 0, проверены пять языков и три темы из шести,
документация подсистем обновлена там, где этап её затронул.
